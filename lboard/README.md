# L-board для телеканала РБК (код формата AIR_LB)

Источник требований — `../ТТ РБК/Техтребования - ТЕЛЕКАНАЛ РБК/ТТ_ТЕЛЕКАНАЛ РБК_05.pdf`,
страница «L-борд» (`tt-lboard-page.png`, превью зон — `tt-lboard-preview.png`).

## Что сдаём

| Параметр | Значение |
|---|---|
| Файл | MOV, ProRes 4444 |
| Кадр | 1920 × 1080 px, 50 progressive |
| Хронометраж | 10, 15 и 20 с — три файла |
| Звук | не требуется (в ТТ L-борда аудио не указано; требования к звуку относятся к MXF-роликам) |
| Анимация | да |

## Геометрия кадра (по превью РБК)

- Баннер занимает весь кадр 1920 × 1080; фон сплошной.
- Сверху накладывается программа: прямоугольник 600…1920 × 0…724 (1320 × 724).
- Снизу накладывается бегущая строка РБК: 96…1824 × 960…1044 (1728 × 84).
- Зрителю видно: левая полоса 600 px на всю высоту и нижняя полоса 356 px на всю ширину.
- Безопасная зона для текста и главных элементов: вертикаль 504 × 912 от (96, 48);
  низ 1728 × 236 от (96, 724). Поля 96 слева/справа, 48 сверху, 36 снизу видны, но вне зоны.

Шаблон с заглушками — в Figma, страница «Баннеры», фрейм
«L-board · шаблон 1920×1080 (РБК ТВ, AIR_LB)» (`figma-template.png`). Служебные слои заперты.

## Макет и сборка

Макет Никиты — фрейм «L-board · шаблон 2» (2037:987) на странице «Баннеры». Слои: плашка
«в компании художников» (104, 108), заголовок в три строки (106, 194), подзаголовок про
приложение (105, 395), логотип (104, 825); в нижней полосе конь (718, 762), круг с горами
(1169, 595 — верхом уходит под программу, так задумано) и пара (1633, 741).

Слои в `assets/`: тексты и логотип — из SVG-экспорта Figma (у PNG-экспорта всегда подложка:
Figma подмешивает фон фрейма или канвы), отрисованы в PNG @2x через `tools/svg2png.js`;
заголовок разрезан на три строки по прозрачным рядам. Иллюстрации — PNG @2x, серая подложка
канвы выбита по цвету (их родные контуры чёрные, бахромы не видно).

`index.html` — сцена 1920×1080. Вход элементов — язык утверждённых билбордов (иллюстрации
снизу, плашка → строки заголовка → подзаголовок → логотип со «смазом» слева, всё за 2,7 с).
Дальше покой, вариант выбирается параметром `?v=`:

- `A` «дыхание» — конь чуть поднимается (1,2 %, 9 с), круг дышит (3 %, 11 с), пара покачивается
  (±0,4°, 12 с) — ровно то, что живёт в HTML-баннерах;
- `B` «наезд» — одна медленная камера: иллюстрации нижней полосы растут до 105,5 % за 17 с
  от нижней кромки, текст стоит;
- `C` «дыхание + блик» — A и два прохода тёплого блика по логотипу (на 7-й и 9-й секунде, 2,2 с каждый).

`?overlay` рисует заглушки эфира и бегущей строки — для черновика на согласование.
Ухода нет: последний кадр держится до конца, эфир сам снимает баннер.

## Как рендерится

Та же схема, что у HTML-баннеров: слои и CSS-анимация в `index.html`, затем
`tools/render.js` гонит headless Chrome по кадрам (50 в секунду, `document.getAnimations()`
ставится на нужное время) и отдаёт их ffmpeg в ProRes 4444.

```bash
cd lboard/tools && npm i          # один раз, puppeteer-core берёт установленный Chrome
node render.js ../index.html 20 ../dist/draft_A_20s.mp4 25 0 "v=A&overlay"   # черновик, H.264, ~1 МБ
node render.js ../index.html 20 ../dist/lboard_20s.mov 50 0 "v=A"            # сдача, ProRes 4444
```

Если файл `.mp4` — H.264 (crf 20, yuv420p), иначе ProRes 4444; пятый аргумент `1` включает альфу.
Хронометраж задаётся вторым аргументом, кадры считаются точно: 20 с × 50 = 1000 кадров.

Пилот 2 с (`pilot.html`) — 100 кадров за 8 с; 20-секундный файл ≈ 1,5 минуты. Проверка:
`ffprobe -show_entries stream=codec_name,profile,width,height,r_frame_rate,nb_frames <файл>`.
